Makes a WordPress site installable as an app: manifest, offline service worker, generated icons and an install prompt. No build step, no external services.

== Description ==

Beaver PWA gives a WordPress site the three things a browser looks for before it offers to install it on a phone or a desktop: a web app manifest, a service worker, and a complete set of app icons. All three are generated by WordPress on request. Nothing is written to the site root, nothing is compiled, and no third party service is contacted.

**Nothing to configure to get started**

The app name, short name and description fall back to the site title and tagline, and the icon falls back to the site icon. Activating the plugin is usually the whole setup. Every field is there to override a default, not to fill in a blank.

**Icons are rendered, not requested**

Every size the manifest advertises is produced from one source image with the GD library that ships with PHP, so the set is always complete and correctly sized. That includes a maskable icon: Android crops home screen icons to a circle, so the artwork is inset on the splash background colour and nothing important is cut off. Change the source image and the whole set is rebuilt.

**An offline cache that will not embarrass you**

Pages are always fetched from the network first and kept only as an offline copy, so nobody reads yesterday's article from a cache. Stylesheets, scripts and fonts are served from the cache and refreshed in the background. Images are cached with a hard entry limit so a large media library cannot fill a visitor's phone.

Admin screens, the login page, the REST API, feeds, previews, page builder editors and WooCommerce cart, checkout and account pages are never stored. Neither is anything WordPress marks as private, which is what keeps a signed-in visitor's pages out of the cache without turning the app off for them.

**A prompt that only appears when it will work**

The install card stays hidden until the browser confirms the site can actually be installed, so it never advertises something that cannot happen. Safari on iOS has no install button at all, so the card shows the share menu instructions there instead. Dismissals are remembered for as long as you choose, and the card never appears again once the app is installed.

**It cleans up after itself**

A service worker outlives the page that installed it, which is how sites end up frozen in visitors' browsers long after a plugin is switched off. This one checks in with the site each time it starts. If the plugin has been disabled or removed, it clears its caches and unregisters itself instead of serving a stale copy of the site for ever. A failed request proves nothing, so only a definite answer from the server counts.

**Features**

* Web app manifest generated on request, with name, short name, description, colours, display mode, orientation, start page, categories and app shortcuts.
* App icons rendered at 192 and 512 pixels, plus a padded maskable icon and an Apple touch icon.
* Up to four long-press shortcuts built from your pages.
* Offline fallback: a self-contained built-in page that also lists the pages already saved to the device, or any page of your own.
* Separate page, asset and image caches, each with its own entry limit and its own strategy.
* Exclusion list for anything else that must never be cached, on top of the built-in exclusions.
* Install prompt with configurable position, delay, message, button label and dismissal period, plus an `[beaver_pwa_install]` shortcode for placing a button in your content.
* Add to Home Screen instructions for Safari on iOS, shown only there.
* Optional refresh prompt when a new version of the app is ready.
* Readiness checklist that requests the live URLs over HTTP rather than reading the settings, so an unflushed rewrite rule or a proxy rewriting a header is caught.
* Every settings change invalidates the caches held in visitors' browsers automatically.
* Works with or without pretty permalinks: the endpoints fall back to query strings, which still gives the worker the whole site.
* WP-CLI commands for status, cache invalidation, icon rebuilds and manifest output.

== Installation ==

1. Upload the `beaver-pwa` folder to `/wp-content/plugins/`.
2. Activate the plugin through the Plugins screen in WordPress.
3. Go to **Beaver PWA → Dashboard** and read the Readiness panel.
4. If a site icon has not been set, set one under **Settings → General**, or choose a dedicated app icon under **Beaver PWA → Settings**.

The site must be served over HTTPS. Browsers refuse to register a service worker on an insecure origin, with the single exception of `localhost` for development.

== Frequently Asked Questions ==

= Why is the install prompt not showing? =

Open **Beaver PWA → Dashboard** and press Re-run checks. The prompt is deliberately hidden until the browser fires its own installable event, so anything the checklist reports as blocking will also block the prompt. Chrome also requires a visitor to have interacted with the page before it fires the event, and it never fires again once the app is installed.

= Does this work on iPhone? =

Yes, through Safari's share menu: there is no install button on iOS for any site. Turn on the iPhone and iPad hint and the install card shows those instructions in Safari instead of a button.

= Will visitors see stale pages? =

No. Pages are fetched from the network on every visit and the cached copy is only used when the network fails. Saving the settings, invalidating from the dashboard or updating the plugin all change the cache signature, which makes every browser download a fresh copy.

= What happens to visitors who already installed the app if I deactivate the plugin? =

The worker asks the site whether it is still wanted each time it starts. Once the plugin is off, that request is refused, and the worker clears its caches and removes itself. Visitors fall back to the normal site.

= Does it work with a caching plugin or a CDN? =

Yes, with one caveat: the service worker must reach the browser as JavaScript with its `Service-Worker-Allowed` header intact. The Readiness checklist requests the real URL and reports both, so a proxy that rewrites either is caught immediately.

= Can I put an install button in a page? =

Use `[beaver_pwa_install]`, optionally with `text` and `class` attributes. The button stays hidden until the browser confirms the site is installable.
